# YOLOE 本地实验台

运行在本机的图片推理 DEMO。无需前端构建，无云端上传，不修改 Ultralytics 核心代码。

## 启动

Windows 双击 `start.bat`。默认打开 <http://127.0.0.1:8765>，关闭终端停止服务。
本次交付环境已安装依赖并缓存 YOLOE-26n 的普通/无提示权重和文本编码器。

也可在本目录运行：

```powershell
.\.venv\Scripts\python.exe server.py --directory "D:\images"
```

端口占用时使用 `--port 8766`。`--no-browser` 只启动服务。

首次安装需要 Python 3.12、Git 和网络。启动脚本创建独立 `.venv`，可复用本机已有包；会验证真实 NMS 操作。缺失或不匹配的环境使用 PyTorch 2.13.0 / torchvision 0.28.0 CUDA 13.0 配对。其他驱动版本请按照 [PyTorch 官方安装表](https://pytorch.org/get-started/previous-versions/) 安装匹配版本，也可使用 CPU。

文本编码器的 CLIP 依赖固定为官方仓库提交 `7ffa84b3bfa40c42ecc1c77147a855e69cb2dd40`，安装时不重新解析 torch 依赖。服务关闭运行时自动安装，防止已经加载的 CUDA 包被中途替换。

## 使用

1. 粘贴目录路径并点击“打开目录”，或“浏览…”调用本机文件夹选择器。支持递归子目录、中文路径、文件名搜索、分页、左右方向键切图。
2. 在左侧选择图片。视觉模式点击“使用当前图片”固定参考图，然后标注。跨目录时先固定参考图，再打开另一个目录，参考提示仍保留。
3. 每一类都需要名称和至少一个示例，同一类可标多个。点击类别编号切换标注类别。支持删除单个标注、撤销、清空和缩放；缩放后的坐标自动还原到原图。
4. 点击“待测图片”，选择另一张图片并推理。批量操作使用固定参考图检测整个目录，包括未被搜索结果显示的图片；图片不会被改写。
5. 首次选择某模型会自动下载权重。文本首次运行另下载编码器。下载/编码阶段无法即时取消，取消会在进入下一张图片前生效。
6. 通过“查看结果”切换任务记录，通过检测框、掩码、提示开关切换叠加层。结果为零会明确显示未检出。
7. “保存提示”下载参考图标识、类别和形状 JSON。再次打开原参考图目录后可“载入提示”。原图移动或重命名后需要重新标注或更新提示文件。

## 支持边界

| 能力          | 实现                                                                                         |
| ------------- | -------------------------------------------------------------------------------------------- |
| 文本提示      | 官方 `YOLOE.set_classes()`，每行或逗号分隔类别                                               |
| 无提示        | 专用 `*-seg-pf.pt`，使用内置词汇，不传文本/视觉提示                                          |
| 框提示        | 官方 `YOLOEVPSegPredictor.set_prompts()` + `get_vpe()`                                       |
| 点选区域      | 将点转换为可调半径的圆形掩码，不是正负点分割                                                 |
| 画笔          | 鼠标轨迹生成区域掩码                                                                         |
| 多边形        | 连续点选，双击闭合，填充内部生成掩码                                                         |
| 掩码编码      | 官方 `LetterBox` 对齐图像和掩码，`LoadVisualPrompt.get_visuals()` 栅格化，官方预测器提取 VPE |
| 同图/跨图     | 将参考图的 VPE 通过 `set_classes(names, embeddings)` 应用到目标图                            |
| 多类别/多实例 | 按类别聚合示例，不同类别都必须有提示                                                         |
| 检测与分割    | 同一分割模型同时输出框和多边形，界面可分别显示                                               |
| 批量          | 顺序推理，进度、取消、单任务互斥，模型只加载一次/任务                                        |
| 提示复用      | 标注 JSON 和官方 `save_prompt_embeddings()` 的 NPZ                                           |
| 模型选择      | YOLOE-26 n/s/m/l/x、11 s/m/l、v8 s/m/l，匹配无提示权重                                       |

点/画笔/多边形是 DEMO 的交互输入，经区域掩码送入官方视觉编码器。不能据此宣称 YOLOE 高层 `predict(visual_prompts=...)` 原生支持 SAM 式正负点。多个视觉示例来自一个参考图；不进行跨参考图的向量融合。

本 DEMO 的“全部功能”范围是图片提示推理。训练/微调、数据集验证评测、视频跟踪、部署格式转换不是该图片界面的功能。这些流程仍使用官方 Python/CLI 接口。模型输出需人工复核，少样本外观提示不保证跨场景召回。

## 结果文件

每次任务创建独立 `runtime/<任务ID>/`，失败/取消也保留已有结果，不覆盖原始标签。

- `request.json`：模式、模型、参数、提示与输入图片 ID。
- `job.json`：状态、完成数量、耗时与输入映射。
- `<图片ID>.json`：原图路径、原图尺寸、类别、置信度、像素检测框、分割多边形、官方分阶段计时。
- `<图片ID>.txt`：YOLO 检测格式，`class cx cy w h`，归一化到原图。
- `<图片ID>.seg.txt`：YOLO 分割格式，类别后为归一化多边形坐标。
- `<图片ID>.jpg`：带结果叠加的预览，不能直接作为训练原图。
- `classes.json`：编号与名称映射。
- `prompt.npz`：文本/视觉任务的官方提示向量，可加载到同架构权重。

文件用路径摘要 ID 命名，避免不同子目录同名图片覆盖；使用 JSON 中 `path` 关联原图。无检测目标也生成空标签文件。ZIP 导出整个任务目录。界面的毫秒数为官方预处理、推理、后处理耗时之和，不包含模型下载/载入、文件保存等总开销。

仅绑定 `127.0.0.1`。模型、文本编码器与结果保存在 `runtime`；这些文件和 `.venv` 不进入 Git。服务重启保留已完成记录，未完成任务不能断点续跑。浏览器刷新会丢失未保存的标注，请使用“保存提示”。系统文件夹选择器不可用时，直接输入目录路径。
